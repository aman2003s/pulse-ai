# Pulse — Master Flow Plan (end-to-end, production-ready, fully hands-free)
_The single tracking file for taking Pulse from "works sometimes" to production. Execute stages top-to-bottom; each stage is verified and solidified before the next starts. Updated 2026-07-25 after full internet validation of every component._

**Goal:** a completely hands-free, offline-first voice assistant that replaces NVDA/JAWS-style interaction, controls the whole PC, answers questions like a normal AI assistant (with internet access only when a question needs current info), built exclusively on commercially-free open-weight models. Auto-startup deliberately deferred to ship time (we're in development); everything else must be voice-completable.

### 1.2 Wake word — how false accepts are actually eliminated (validated vs. Home Assistant / microWakeWord / Picovoice practice)
Industry standard is **layered rejection, tuned against "false accepts per hour of ambient noise" as the primary metric** (accuracy second):
1. ✅ Sustain window (we ship 2-of-4 raw frames) — matches microWakeWord's sliding-window averaging.
2. ✅ Refractory debounce (2s).
3. ❌ **VAD gate** — the industry-confirmed biggest lever for non-speech noise (air, fans, typing): only accept detections when speech is simultaneously present. Built into our installed openWakeWord (`vad_threshold`).
4. ❌ **Second-stage verifier** — openWakeWord's `custom_verifier_models`: per-user logistic verifier trained on the 5 enrollment samples we already record.
5. ⚠️ Noise-class negatives in training (fan/air/breath/keyboard/TV) — partial today (word negatives only).
6. ❌ Threshold calibration measured against a recorded noise soak, not guessed. Typical production trigger confidence 0.9+ on smoothed output; our idle 0.3 is far below practice.

### 1.3 UIA (screen intelligence) — current facts that shape the flows
- Chrome ships a **native UIA provider** (rolled out from v126) — browser reading/clicking works first-class. Firefox/Edge similar.
- **Electron apps need `--force-renderer-accessibility`** or their tree is empty → flows must detect an empty tree and degrade honestly (say so + fall back to `send_keys` shortcuts), never silently stall.
- `uiautomation` (our wrapper) covers MFC/WinForms/WPF/Qt/Chrome/Electron — validated as the right library; FlaUI-style "structured accessibility tree + element refs" is exactly the pattern our `read_screen` numbered-elements design already follows.
- UAC/secure-desktop prompts: blocked for normal processes — **but NOT for registered assistive technology.** With a `uiAccess=true` manifest (signed binary, installed under Program Files), Windows grants exactly what screen readers like NVDA use: `SendInput` into higher-privilege windows, foreground control, and secure-desktop interaction. Dev builds: narrate-only. Ship builds: full UAC interaction via UIAccess (→ 7.8).

### 1.5 Input simulation — the "virtual keyboard/mouse" architecture (validated)
Windows gives three tiers of synthetic input; Pulse uses the right one per situation instead of one blunt instrument:
| Tier | Mechanism | Reach | Status |
|---|---|---|---|
| 1. Semantic (preferred) | UIA patterns — Invoke/Toggle/SelectionItem/Value | Any UIA app, no cursor movement, DPI-proof, background-safe | Partially built (Invoke + Value); ladder = 4.6 |
| 2. **OS-level virtual input** | **`SendInput` — the official virtual keyboard/mouse.** Events enter the same system input stream as real hardware; apps cannot tell the difference in normal use. Covers coordinates-based clicks, drag, scroll, hotkeys, typing. | Every same-privilege app, incl. apps with no/poor UIA tree | Already what our fallbacks use (`keyboard` lib, `el.Click()`); needs the guards in 4.7 |
| 3. UIAccess (ship) | `uiAccess=true` manifest + Authenticode signing + Program Files install → Tier 2 reach extends to elevated windows & UAC secure desktop — the legal, AV-safe, Microsoft-designed AT path | Everything a screen reader can touch | Ship item 7.8 |
| ~~4. Kernel virtual HID driver~~ | Interception/custom KMDF driver | Anti-cheat games etc. | **Rejected**: driver signing costs, AV flags, security liability — zero benefit for our use case over Tier 3 |

### 1.4 Conversation design (validated against 2026 voice-agent practice)
- Barge-in: on wake-word during TTS → stop playback immediately, capture the full new turn. (We have this; it must also work during fast-path speech.)
- Multi-turn context: "open the second one" resolves from conversation history (our ConversationManager) — context carry is table stakes.
- Slot filling: production systems use **external state machines / checkpoints** for required slots, not LLM-prompt hope — matches our park/`pending_slot` design.
- Follow-up mode: after a completed exchange, a short re-listen window without re-waking is the modern default (Alexa Follow-Up style) — adopted below as **J3 follow-up window** (Superhero: always on; Standard: on after questions only).

## 2. The Contract (rules every flow must obey — no exceptions, ever)
1. **Resolve before you speak.** Never announce an action until the target is verified to exist.
2. **Every spoken word has matching UI text** (one speech gateway; audio and pill never disagree).
3. **Anything destructive goes through `ToolExecutor`** (confirm/timeout/verify). No lane calls `tool.execute()` directly.
4. **Any state with audio playing is barge-in interruptible.**
5. **Hands-free is a guarantee.** Every interaction voice-completable; buttons/typing are alternatives. (Auto-startup: deferred to ship checklist, everything else applies now.)
6. **Offline-first.** Only `web_search`/downloads touch the internet; every internet feature degrades gracefully and honestly when offline ("I can't check online right now — from my own knowledge…").
7. **No AI in routing.** Static lane = deterministic normalizer + command table over real indexes. AI lane = everything else. A wrong static match is worse than a slow AI answer → precision first, AI is the fallback.

## 3. Journey map (every workflow, end to end)

- [ ] **J1 — Startup → Ready (dev mode).** `run.bat` → llama-server spawn (port fallback exists) → models load → WS on 7550 → UI pill connects → **spoken "Pulse is ready"** → idle. Model file missing/corrupt → spoken error naming the fix. (Watchdog + autostart: ship checklist.)

- [ ] **J2 — Idle loop (always on).** VAD-gated wake stream (<5% CPU) ∥ screen-cache refresh on focus change ∥ optional narration/typing-echo. Speaks nothing unsolicited unless narration mode is on.

- [ ] **J3 — The spine: wake → route.** Wake hit → earcon + `listening` → capture until silence (Silero end-pointing) → Moonshine STT with vocab biasing → transcript broadcast to UI → **normalizer** (strip politeness/filler) → static table exact match? → **J4**; else → AI planner → J5/J6/J7/J8. After any completed exchange that asked a question — and after *every* exchange in Superhero — open a short **follow-up window** (~5s re-listen, no wake word needed, earcon-marked); silence just closes it.

- [ ] **J4 — Static action (no AI ever).** `open/close/launch/show <known entity>`: resolve against `app_index`/known folders/`file_index`/screen cache **first** (<10ms) → found: speak "Opening X" (hybrid prefix, `speaking` state) + execute via ToolExecutor → verify → done. Not found → hand the *original utterance* to the AI lane silently (it can search or ask). Destructive rows (`close_app`) → executor's confirm gate fires (J7-style yes/no). Target: voice-to-action <1.5s.

- [ ] **J5 — Assistant Q&A.** Planner detects a question, no screen action. Answerable offline → answer directly. Needs current info → connectivity check → `web_search` (DDG now, SearXNG option at ship) → answer citing "according to <site>". Offline → honest sourcing disclaimer (already in prompt). Long answers stream sentence-by-sentence, barge-in interruptible.

- [ ] **J6 — Screen intelligence.** "Read/summarize the screen / this article / this PDF" → UIA text extraction from focused window (Chrome native UIA ✅) → short content: read directly; long content: LLM-summarize or read in sections with "continue?" checkpoints (Guided) / continuous with barge-in (Standard). Empty UIA tree (Electron w/o flag) → say exactly that + offer keyboard-shortcut fallback. UAC/secure desktop → narrate what's on screen, state that Windows requires a physical click.

- [ ] **J7 — Missing information (single step).** Detect missing slot → ask **only that slot** ("Where should I save message.txt?") → capture in follow-up window. Answer → proceed. Silence → slot has safe default: announce + proceed ("No answer — saving to your Desktop."). No safe default → **Standard:** park (status `waiting_input` + `pending_slot`, spoken hold message) → **Superhero:** narrate current screen/task state first, then park. Confirmations (destructive) are never defaulted to yes — silence = no, task parks awaiting explicit yes.

- [ ] **J8 — Multi-step execution.** Planner returns `task_list` → narrated decomposition ("I'll do this in 3 steps…") → per-step act-observe loop (read_screen-verified, never guessing element indexes) → mid-task dialogs (save/overwrite prompts) detected via UIA → narrated + voice-answered → **save semantics:** new/Untitled doc → counter-question (Desktop default); existing doc → silent Ctrl+S → completion summary; Superhero adds "What would you like next?". Any step may invoke J7. "Stop/cancel" or barge-in + new command → current task parks with progress intact.

- [ ] **J9 — Interruption.** "Pulse" during any speech → TTS cancelled <200ms → listening. New utterance = new command; if a multi-step task was mid-flight it parks first (spoken: "Pausing that."). Explicit "stop / cancel / never mind" → cancel + confirm cancellation in one short phrase.

- [ ] **J10 — Park & resume.** One parked task at a time (newest wins; replacing speaks a one-line notice). "Continue / resume / where were we" → one-line context restatement → re-ask the pending slot or resume the pending step. Parked state survives in SQLite (already has `plan_json`/`current_step`/`history_json`).

- [ ] **J11 — Errors & recovery.** Empty STT → "I didn't catch that" once, then idle (never loops). Tool error → spoken plainly + park if mid-task. Planner timeout → apology + idle. Mic device lost → auto-reconnect + spoken notice on surviving output. "Are you there?" → speaks state + active/parked task. "Start over" → hard reset to idle. All spoken text mirrored to pill (Rule 2).

- [ ] **J12 — Settings & personalization (all voice, static lane).** Superhero/narration/echo/speed toggles (exist) + voice picker, mic picker, "open/close settings" (to add). Wake-word training: existing guided 5-sample flow, extended to also train the per-user verifier (1.4) and to replace (not accumulate) old samples.
